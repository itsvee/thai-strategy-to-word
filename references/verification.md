# ตรวจรับก่อนส่ง

## Gate และเนื้อหา

- มีโจทย์ยืนยัน revision ปัจจุบัน และตัวตรวจ ready_for_analysis จริง
- ไม่มีข้อขัดแย้งที่เปลี่ยนข้อสรุปถูกปิดด้วยสมมติฐานเงียบ ๆ
- ปัญหาไม่ใช่เพียงคำกว้างหรือชื่อวิธีแก้ และแผนเชื่อมกับเหตุการณ์ที่ผู้ใช้ระบุ
- ข้อมูลภายในมีช่วงเวลาและสถานะ ไม่เผยแพร่สิ่งที่ผู้ใช้ไม่อนุญาต
- Framework แต่ละชิ้นมีผลต่อการตัดสินใจ ไม่ใช้จำนวนตารางแทนความครบ
- บริษัท กลุ่มลูกค้า ระดับกลยุทธ์ และผู้อ่านคงเส้นคงวา
- ทุกเป้าใหม่ติดป้ายข้อเสนอ ไม่อ้างว่าเป็นผลจริงหรือมติอนุมัติ
- ทุก KPI มีสูตร ตัวหาร ขอบเขต ค่าฐานหรือแผนเก็บ เป้า กำหนด owner รอบวัด
- ฐานรายเดือนเทียบรายเดือน ฐานรายปีเทียบรายปี นิยามคงเดิมและไม่ตัดรายการล้มเหลวเพื่อให้ผลดีขึ้น
- Roadmap กับ Gate ไม่ขัดกัน งบรวมไม่ซ้ำและบวกได้ หากไม่มีวงเงินไม่แสร้งว่าอนุมัติงบได้แล้ว
- RACI มี A เดียวต่อโครงการ Risk Register มี owner และ trigger พร้อมการยอมรับคงเหลือ
- ไม่ใช้ GMV เป็นรายได้ เวลาที่คืนมาเป็นเงินสด หรือผลก่อน–หลังเป็นเหตุและผลอัตโนมัติ
- การอ้างกฎหมาย มาตรฐาน ESG/GRI และผลสิ่งแวดล้อมตรงขอบเขตหลักฐาน
- ผู้บริหารอ่านบทสรุปแล้วทราบว่าต้องตัดสินใจอะไรและข้อจำกัดคืออะไร

## ภาษาและไฟล์

- ไม่มีหัวข้อคำถามหรือรูปแบบตอบโจทย์ชั้นเรียนในเนื้อหาหลัก
- ภาษาไทยตามคู่มือ มีเหตุผลต่อเนื่อง ไม่เป็นรายการศัพท์ Framework
- ไม่มี placeholder, TODO, ช่องที่ยังไม่กรอก หรือรหัสงานภายในที่หลุดเป็นข้อความส่งมอบ
- แหล่งอ้างอิงมีจริงและตรงสิ่งที่ใช้ ไม่เรียกผลค้นย่อว่าอ่านเอกสารเต็ม
- สร้าง Word เมื่อร้องขอ ใช้ bundled thai-docx ก่อน หากต้องใช้วิธีสำรองให้บันทึกวิธีและตรวจความตรงกับต้นฉบับ อ่าน exit code และ warnings จริง
- ใช้ bundled check เมื่อ runtime พร้อม และเปิด/เรนเดอร์ตรวจหน้าเปิดกับตารางเมื่อทำได้
- หากฟอนต์พรีวิวไม่พร้อม แก้การค้นหาฟอนต์ของ renderer ไม่แก้ตัวสะกดหรือเพิ่มช่องว่างเพื่อทำให้ดูผ่าน
- ตรวจภาพเฉพาะหน้าที่อ่านจริงแล้วรายงานขอบเขต ไม่อ้างตรวจทุกหน้าเมื่อสุ่มตรวจ
- ส่ง HTML เป็นค่าเริ่มต้น พร้อม DOCX เมื่อร้องขอ เก็บ Markdown เป็น source ภายใน เปิด HTML ตรวจสารบัญ ลิงก์ ตาราง และเชิงอรรถ บอก settings และข้อจำกัดของ Word ตามผลจริง

## เกณฑ์หยุด

ไม่มีการสร้าง Word ก่อนผ่าน Business Gate แม้ผู้ใช้ขอ “ทำเลย” ถ้ายังขาดโจทย์ ให้ถามช่องว่างที่จำเป็นและอธิบายว่าจะทำให้เลือกกลยุทธ์ผิดอย่างไร ถ้าผู้ใช้ขอหยุดสัมภาษณ์ให้ส่งเฉพาะ checkpoint และแผนเก็บข้อมูล ไม่อ้างว่ารายงานสมบูรณ์ ผู้ใช้สามารถเปลี่ยนขอบเขตเป็นบันทึกสำรวจได้ แต่ต้องยืนยันขอบเขตใหม่นั้นก่อนวิเคราะห์

เมื่อสร้างและตรวจครบแล้วให้หยุดและส่งผล ไม่ทำ audit ซ้ำหรือเพิ่ม Framework นอกขอบเขตโดยไม่มีเหตุใหม่
